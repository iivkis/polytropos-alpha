# P0/P1 implementation status (dev)

This file records the supported scope of the implementation. VN-P01–VN-P06 now have a complete P0 acceptance path in that explicitly bounded scope; VN-P07–VN-P12 remain P1 work. "Complete" does not mean arbitrary Lean/Rust predicates, arbitrary atomic math, IEEE-754 machine proof or signed provenance.

Implemented API slices:
- **P01/P03**: `MathContract::with_claim` declares independent ideal-Int `Nonnegative` and `EqualsInput` goals. Lean emits distinct theorems. An unsupported nonnegative proof fails closed; an invalid equality has an independently stated theorem that Lean must reject. `node_*_semantics` remains only definitional equality.
- **P02**: versioned `PrimitiveSpec` expressions built from existing typed operations, lowered to ordinary IR and hence supported Lean/GPU paths; opaque callbacks and new atomic math are not accepted.
- **P08**: first atomic conditional tensor slice: `Operation::PositiveMask` creates canonical 0/1 elementwise masks using strict x>0, and `SelectPositive` selects unmodified elements from equally shaped branches. Both have checked Rust IR/host f32 semantics and independent Lean ideal-Int definitions, pointwise lemmas and nonnegative composition. They can be used within `PrimitiveSpec`, named multi-output consumer modules and fixed scans, including a finite-horizon global state invariant. For now `GpuEngine`, `ExactFp32Plan` and dyadic RNE planners reject both operators: no CUDA kernel, threshold stability proof, IEEE NaN correspondence or machine guarantee is claimed. `task proof-gated-select` exercises Lean and explicit GPU fail-closed plus host special-value fixtures.
- **P04**: module bodies cannot capture undeclared external nodes, return an output they do not own, or introduce hidden inputs. Both single- and multi-output invocations now record the full half-open owned body range `[body_start, body_end)`, so ownership does not silently stop at the returned output node. Nested module bindings, application order and rollback are checked.
- **P05**: `ProofGoal` supports independently named nonnegativity/equality. Ideal-Int `Nonnegative` module and multi-port claims now use recursive proofs from graph operation lemmas and explicit source hypotheses even when the separate FP32 domain is `Any`; unsupported source assumptions fail closed. `generate_fixed_scan_nonnegative` composes checked local claims into a distinct theorem about every state over a requested finite horizon. Generic arbitrary predicate/theorem-definition reuse is still open.
- **P06**: `verify_certified` reruns Lean `#print axioms`, checks the exact theorem identities, and records every transitive axiom dependency. Only foundational `propext` is allowlisted as explicit Lean TCB; `sorryAx`, user axioms, `Classical.choice` and unreviewed axioms fail closed. Stage 5 issue/replay compare the saved checker version, axiom policy and actual dependencies. Other evidence paths still need integration.
- **P07**: atomic named multi-output module boundary, stable `output_named` lookup, and `LeanProofEngine::generate_outputs` generating one ideal-Int Lean artifact for multiple chosen outputs (including fork/fan-in consumers). Each reachable named input/output port has explicit shape obligations; supported output domain and user claims generate separate theorems. Unsupported input claims are rejected at construction instead of silently ignored. This is *not* yet universal global theorem composition across multi-output boundaries.

- **P05/P12 automation slice**: `ArchitectureAutoCompiler` accepts the consumer's `NeuralGraph`, selected outputs, and independent `ArchitectureProofTask` goals. `plan` rechecks every graph edge, module port, input/output shape/domain, module-body captures and topological order, then generates the combined Lean model and all explicitly requested property programs, and plans NVPTX for each output. `build` fails closed on Lean kernel/axiom audit failures, regenerates artifacts in its reserved `auto-build/` directory, emits per-output LLVM/PTX plus translation validation, and records conditional Lean hypotheses, reviewed axiom dependencies and accurate unsupported-GPU reasons. `GpuRequirement::AllOutputs` enforces full GPU operator support while `AllowUnsupported` permits Lean-only outputs with explicit unsupported status. `task auto-architecture` is a consumer fork/fan-in example with two reusable activated components, a merge contract and an independent global proof goal. Connectivity validation is a Rust structural audit, **not** a formal proof that the GPU machine code implements the same wiring or FP32 semantics. The API still does not unify runtime execution or implement a shared multi-output GPU execution graph. Canonical SHA256SUMS replay and full auto DOT/PNG were added in subsequent slices.
- **P06/P12 replay slice**: `ArchitectureAutoCompiler::build` now writes the same explicit versioned graph-only `NeuralGraph::canonical_ir()` used by the other artifact paths. Selected outputs, proof tasks and GPU requirement are build-plan concerns rather than duplicated semantic-IR fields; the complete expected artifact set plus `SHA256SUMS` binds those choices for replay. `verify_bundle` reconstructs the current plan, compares the canonical graph IR, checks the expected file set and digests (optionally against an externally pinned manifest digest), reruns Lean kernel plus axiom audits and re-validates PTX translation against regenerated LLVM/IR plans. `task verify-auto-architecture` exercises the offline replay. The manifest provides integrity relative to a separately pinned SHA-256 digest, **not authenticity**. Still no machine-level FP32 correspondence or signed provenance.
- **P07/P12 auto-visualization slice**: `ArchitectureAutoCompiler::build` also generates one complete deterministic `auto-build/architecture.dot` from the canonical `semantic.ir`, including all graph nodes, typed IR dependencies, ordinary/multi-output nested module clusters, named state/readout input/output ports, shapes/domains/contracts, reachability and distinct ideal-Lean/GPU-lowering statuses. Snapshot and auto-build now share one normalized module hierarchy and real application order instead of independently rebuilding single/multi ownership. The DOT embeds the precise `vn_ir_sha256`; pinned Nix Graphviz renders `architecture.png` from this DOT. DOT/PNG are recorded in `SHA256SUMS`; `verify_bundle` recomputes DOT, re-renders PNG with the pinned renderer and compares both byte-for-byte with the saved files. Zero fake port/relay arrows, one visible edge per actual IR input. SVG/PDF, auto-role classification (inputs versus parameters/state), arbitrary dtype and machine-code correspondence remain unsupported.
- **P01/P03/P05 relational proof slice (ожидает локальной Lean-проверки)**: `MathContract::predicate`/`NamedPortContract::predicate` и `ProofGoalKind::Predicate` используют единые `Predicate` + `ValueRef`. Реализованы декларативные `Nonnegative`, `Equal`, `PointwiseLe`; `PointwiseLe` доказывается через независимую ideal-Int лемму `pointwise_le_relu` и Lean kernel, а не из одного объявления. IR fingerprint включает контракт; неправильные ссылки, формы и неподдерживаемые отношения fail-closed. В `tests/relational_predicates.rs` есть положительный и отрицательный consumer-примеры и отдельная opt-in команда `task verify-relational-predicates`, запускающая Lean и axiom audit. Это только первый ограниченный фрагмент, **не** поддержка произвольных Rust/Lean предикатов и не FP32/GPU equivalence.
- **P08 axis reduction slice (ожидает локальных проверок)**: `NeuralGraph::reduce_sum(input, axis)` и `Tensor<f32>::reduce_sum(axis)` реализуют shape-safe row-major суммирование по произвольной оси с фиксированным порядком аккумуляции. Canonical IR и DOT сохраняют ось, Lean `reduceSumAxis` задаёт идеальную `Int`-семантику и `reduceSumAxis_nonnegative` формально выражает сохранение неотрицательности входа. Consumer `tests/tensor_reductions.rs` проверяет первую/среднюю/последнюю оси, scalar output, rollback при неверной оси, комбинацию с пользовательским atomic Pointwise, отрицательное proof obligation и отсутствие фиктивного GPU lowering. Отдельный Lean acceptance: `task verify-tensor-reductions`. Не заявлять FP32/GPU доказательства; общий reduction/numeric/error framework остаётся незавершённым.
- **P02 typed atomic pointwise slice (ожидает локальных проверок)**: `PointwiseSpec` задаёт самостоятельный IR node с внешними `id`, `version`, `arity` и единственным декларативным `PointwiseExpr` из input/add/mul/relu. Верифицируемая ideal-Int Lean-денотация и хостовый f32 reference строятся из того же AST; для финального ReLU независимое доказательство неотрицательности опирается на библиотечную Lean-лемму. Canonical IR и DOT сохраняют версию и выражение, даже если имя примитива совпало. Некорректные порты/формы отвергаются, неизвестный proof rule и GPU/численные backends fail-closed. Независимый consumer `tests/pointwise_primitive.rs`; Lean acceptance по `task verify-pointwise-primitive`. Это **не** универсальный typed tensor-DSL, не произвольный пользовательский lowering и не FP32/CUDA сертификация.
- **P13 API cleanup slice**: common contracts now have `PortContract::any/finite/nonnegative`, claims have fluent helpers, `NeuralGraph::compose` / `compose_multi` let small consumer modules use the same transactional checks without boilerplate Rust types, and `PrimitiveExpr` has chainable constructors (`port`, `matmul`, `bias_add`, `relu`, `select_positive`, etc.). `module_instances()` provides one application-ordered view over single/multi invocations while keeping the existing typed slices for compatibility. This is ergonomics and DRY cleanup, not completion of the generic predicate or arbitrary atomic primitive requirements.
- **P12 shared-output CUDA slice**: `GpuEngine::compile_outputs` now compiles the union of one or more output dependency closures to **one** LLVM NVPTX module and a single CUDA Graph capture. Each shared arithmetic producer has exactly one kernel and device buffer; every requested output remains observable under experimental fusion, source inputs are the union, and `GpuExecution::read_outputs` returns the ordered tensors after one replay. `task gpu-multi-output` is a developer-run Lean + shared CUDA Graph fixture with two input batches. `ArchitectureAutoCompiler` optionally emits separately audited `gpu_shared` PTX and translation plan/validation evidence alongside legacy per-output bundles when *all* selected outputs support GPU compilation; offline verification rechecks it and SHA256SUMS pins it. No shared-output graph when any selected output is unsupported; no claim that Lean's ideal-Int semantics proves NVIDIA machine FP32 or JIT/SASS. The auto compiler still performs backwards-compatible per-output lowering and does not automatically execute on GPU during build.
- **P10**: `ParametricSignature` and consumer `ParametricModule` provide symbolic input/output axes with repeated-symbol unification, fixed axes, positive bounds, upper bounds and divisibility constraints. `apply_parametric_module` specializes them into checked concrete binary32 row-major `MathContract` / `NeuralModule` instances, preserving rollback, claim obligations, and the existing Lean/GPU compilation path. The `task symbolic-shapes` consumer example instantiates one versioned MatMul at two sizes and checks ideal-Int Lean claims plus LLVM NVPTX lowering. This is static specialization only; no runtime-dynamic dimensions, arbitrary dtype, views, strides, new atomic tensor ops or SASS-level proof.
- **P09**: `scan_fixed` builds atomic consumer-defined state/input → next_state/output transitions. `generate_fixed_scan_nonnegative` checks the actual ordered multi-module bindings, requires a consumer-owned `Nonnegative` claim for each next-state, proves the initial state under explicit source assumptions, and generates a separate global Lean theorem that *all* states from t=0 through the concrete horizon are nonnegative. The `task proof-scan-invariant` consumer example asks Lean to verify the local/global theorems and audits axioms. This does not prove arbitrary-horizon induction, IEEE binary32 finiteness, or machine execution.

P0 acceptance gate:
- **VN-P01/P03**: the typed `Predicate` DSL provides independent relational obligations; true and deliberately false contracts are kernel-checked separately, and canonical semantics/version changes alter fingerprints.
- **VN-P02**: an external consumer-defined `PointwiseSpec` creates an atomic versioned semantic operation without editing VeriNeural; host and Lean semantics derive from the same AST, while unsupported GPU/numeric lowering fails closed.
- **VN-P04**: module ownership/capture/port checks and transactional rollback reject hidden dependencies and foreign outputs before commit.
- **VN-P05**: the fork/fan-in auto-architecture now carries multiple independent global goals; unsupported/false component obligations block planning/publication instead of inheriting another goal's status.
- **VN-P06**: the certified Model path records theorem identities, Lean version, transitive axiom dependencies, semantic/identity fingerprints and SHA-256 evidence; replay rejects tampering and forbidden proof dependencies.
- Developer-run aggregate: `task p0-acceptance`. It intentionally invokes the real Lean/LLVM/Graphviz tools and is not run automatically by agents.

Open P1+ requirements:
- **Automation**: broader automatically discharged proof rules, automatic shared CUDA Graph runtime execution from the auto-compiler, certified runtime execution, signed provenance and machine-level ISA correspondence. Auto-build includes SHA-256 integrity plus source-aware replay, but neither proves FP32/NVIDIA machine behavior nor authenticates the publisher. Structural connectivity and local/global Lean properties are distinct claims.
- **P02/P08/P10**: general comparisons, reductions, indexing, scatter/gather, broadcast, arbitrary new atomic semantics, generic dtypes, symbolic shape arithmetic beyond static named-axis binding, dynamic shapes, views/strides/aliasing, and LLVM/PTX lowering with machine/FP32 guarantees for new conditional operators. The supported ideal-Int mask/select proof is a narrow vertical slice, not comprehensive P08.
- **P05/P07/P09**: general user predicate DSL, independently cached module-definition proofs and reusable theorem dependencies, and full state/control IR remain open. P09 now also has a first true arbitrary-horizon ideal-Int slice: one reusable direct-source transition with a consumer-owned Nonnegative next_state claim is lifted to a Lean Nat-recursive state and a `∀ t` invariant theorem. Multi-state transitions, richer predicates and FP32/runtime induction remain open.
- **P06**: transitive axiom audit integration into every certified artifact, pinned executable/library provenance and reproducible audit evidence.
- **P11/P12**: stable `PositiveMask → SelectPositive` branch inheritance has a conditional dyadic-RNE slice: generic condition interval evidence, selected-branch contract inheritance, explicit `UnstableBranch` on zero crossing, and Lean composition lemmas with concrete margins. Fixed-horizon recurrent error carry is also implemented for one explicit state via source-contract overrides and invariant q-scale. Still open: general comparisons/nonlinearities, arbitrary-horizon recurrent induction, multi-state numerical composition, backend capability proof obligations for every optimization and full machine-code correspondence.

Do not label these incomplete areas certified. The generated bounded scan theorem must pass the external Lean checker and axiom audit; code generation alone is not a proof. Local Rust, Lean and CUDA build/test commands were not executed by the agent per AGENTS.md.


- **Rotating-matrices structural P0 closure (код; локальная приёмка ожидается):** narrow GPU lowering + translation audit + Lean memory-address obligations cover `Permute/ReverseAxis/Concat/ArgMax(First)/Take`. The deterministic laboratory forward now compiles one shared `architecture_model()` CUDA Graph and obtains routing, selected rotation, recurrent transition and readout from that graph; host `route_parts()/rotate()` are no longer part of deterministic inference. Host stochastic sampling remains an explicit training policy, not a second certified deterministic semantics. P1 owns removal of per-token rebinding/state round trips via `ModelExecution`.


- **P1 owned ModelExecution + rotating consumer (код; локальная приёмка ожидается):** `ModelExecution` no longer borrows `&Model`; it owns copied named source/output/state-link metadata while the CUDA execution owns device state. This removes the self-referential storage obstacle for consumers. Deterministic rotating-matrices uses `prepare_model`, uploads parameters/dictionary once per forward, updates only `token_bits` per token, and calls `step()` for D2D recurrent feedback. Reading `next_state` into the returned Trace is observational only and is not rebound into the next step. Stochastic sampling/fixed-route SPSA remains explicit host *route-choice* policy, but execution is now named too: eight route-specific `ModelExecution` instances derive each spatial rotation inside Semantic IR from the two canonical base cores, eliminating host materialization of `rotated_weight` and the lab's raw `GpuExecution` paths.


- **P11 numeric branch slice (код; локальная Lean-приёмка ожидается):** `RneSelectPlan` compiles three ordinary RNE range plans for the condition and two data branches around the canonical `PositiveMask → SelectPositive` boundary. It never treats mask/select as rounding arithmetic. A stable observed condition chooses exactly one branch contract; an interval crossing zero produces no output contract and blocks Lean generation. `RneSelectPlan::lean_program` emits an independently checkable conditional theorem using `approx_contract_positive_mask_select_positive/nonpositive`. Developer gate: `task verify-numeric-branch`.


- **P11 recurrent error rollout (код; локальная Lean-приёмка ожидается):** `RneStateRolloutPlan` composes one explicit state over a fixed horizon by feeding each output `RneErrorContract` back through `RneRangePlan::compile_with_source_contracts`. Adjacent step contracts are numerically identical at the feedback boundary, epsilon is preserved/accumulated rather than reset, and changing the state q-scale is rejected. Each step emits the ordinary reusable Lean range program with the carried state `ApproxContract` as hypothesis. This is bounded contract composition, not an arbitrary-horizon induction theorem. Developer gate: `task verify-numeric-state`.


- **P09 arbitrary-horizon invariant (код; локальная Lean-приёмка ожидается):** `LeanProofEngine::generate_inductive_state_nonnegative` reuses one checked multi-output transition definition and its consumer-owned next_state `Nonnegative` claim in a real Lean induction over `Nat`. Base state and every time-indexed input are explicit hypotheses. The first profile rejects extra hidden sources, non-F32/state-shape changes and missing claims instead of inventing theorem dependencies. Developer gate: `task verify-inductive-invariant`.
